# AGENTS.md

## Project Overview
Electron desktop app for analyzing stocks on the Warsaw Stock Exchange (GPW). Data comes from Yahoo Finance (`yahoo-finance2`) and is cached on disk under `data-cache/`. Main process (Node/Electron) fetches and computes data; renderer (React) displays filters, dividend/valuation screens, and price charts (`lightweight-charts`).

## Architecture
- `src/electron/` — main process (TypeScript, compiled separately via `src/electron/tsconfig.json`).
  - `main.ts` — app entry, creates the `BrowserWindow`, registers all `ipcMainHandle` channels.
  - `stock-data/` — data fetching/computation modules (tickers, historic data, financials, dividend/valuation formulas). Each exported function typically takes the shared `yahooFinance` client and `webContents` (for progress/streaming updates) as parameters.
  - `utils/` — `core.ts` (IPC helpers, `isDev()`), `path-resolver.ts` (preload/UI path resolution).
  - `preload.cts` — exposes the typed IPC bridge to the renderer.
  - `shared-with-ui/` — types/constants shared between main and renderer.
- `src/ui/` — React 19 renderer (Vite).
  - `components/` — one folder per feature (e.g. `advanced-filters/`, `best-dividends/`, `candle-chart/`, `cheap-stocks/`, `filter-tabs/`, `min-max-filter/`).
  - `design-system/` — shared UI primitives (built on `radix-ui` / `@radix-ui/react-icons`).
  - `hooks/`, `utils/` — renderer-side helpers.
  - Styling: CSS Modules with SCSS (`*.module.scss`); typed via `typed-scss-modules` (generated `.d.ts` files — don't hand-edit them).
- `data-cache/` — on-disk cache of fetched data (tickers, historic prices, dividends, quotes, TTM financials), keyed by ticker symbol. Treat as generated/cache data, not source of truth to edit by hand.

## Build and Test
- Install: `npm install`
- Dev (React + Electron together, with SCSS type watcher): `npm run dev`
- Lint: `npm run lint` (ESLint 9 flat config, TypeScript + React rules)
- Unit tests: `npm test` (Vitest; deterministic fixture tests with no network access)
- Yahoo API diagnostic: `npm run diagnose:yahoo [-- SYMBOL.WA ...]` checks live `fundamentalsTimeSeries`, `quoteSummary`, `chart`, and `quote` endpoints. Run it manually when diagnosing source-data issues; never make it a build/PR gate because Yahoo Finance is an unofficial, rate-limited API.
- Production build: `npm run build` (`tsc -b` + `vite build`)
- Electron main transpile only: `npm run transpile:electron`
- Platform installers: `npm run dist:win` / `dist:mac` / `dist:linux`
- Release (Windows): `npm run release:win "<release name>"` wraps `release-it`. The `before:release` hook in `.release-it.json` intentionally builds the installer *before* git commit/tag/push, so a failed build never leaves an orphaned tag on the remote — don't move that hook to `before:github:release`.
- No automated test suite currently exists in this repo.
- After editing any file, check it for compile/lint errors (e.g. via the editor's diagnostics or `npm run lint`) and fix them before considering the change done — don't hand back a file with new errors introduced by your edit.

## Conventions
- When behavior of a third-party library (`yahoo-finance2`, `release-it`, `electron-builder`, etc.) is unclear, verify against its official docs/type definitions before proposing a fix — don't guess.
- Main process and renderer have separate `tsconfig` projects (`src/electron/tsconfig.json` vs `tsconfig.app.json`) — don't cross-import Node-only code (e.g. `fs`, `path`) into `src/ui/`.
- IPC channels are added via `ipcMainHandle` in [main.ts](src/electron/main.ts) and must have a matching typed entry in `preload.cts`.
- `data-cache/` is read/written by main-process modules only; never fetched or written from the renderer directly.
- SCSS module types are auto-generated by `typed-scss-modules` (`npm run scss:types`); if types for a new `.module.scss` file are missing, ensure the watcher script is running rather than writing the `.d.ts` manually.
- `fundamentalsTimeSeries` can return multiple `FINANCIALS` TTM records, including partial older entries. Select the newest record by its `date` before calculating or caching TTM metrics; do not assume the first record is complete.

## Known Gotchas
- `typed-scss-modules` 8.1.1 emits Dart Sass legacy-js-api deprecation warnings during `npm run scss:types` (watch mode); these are safe to ignore.
- DevTools is opened unconditionally in `main.ts` (`mainWindow.webContents.openDevTools()`), which logs benign `Autofill.enable`/`setAddresses` "not found" messages in the console — safe to ignore.
- In Node scripts under `scripts/`, don't spawn npm-installed CLI wrappers (e.g. `npx`, any `.cmd`/`.bat` bin) via `execFile`/`execFileSync` without a shell — they fail to spawn on Windows. Do NOT fix this with `shell: true` + an args array either; Node arguments are only concatenated, not escaped, in that mode (see `DEP0190`) and reintroduce command injection. Instead resolve the target package's actual `.js` entry point and run it via `execFileSync(process.execPath, [entryPath, ...args])` (see `scripts/release-win.js`).
